# Android setup (WSL2 + Windows emulator)

The code and the build live in WSL2. The emulator runs on the Windows host. WSL has no
`/dev/kvm` (nested virtualization isn't available to WSL2 on Windows 10), while Windows has
Android Studio and WHPX acceleration. `adb` in WSL is a wrapper around the Windows `adb.exe`.

## Quick restart

From `gopher-fit-front/`:

```sh
scripts/run-android.sh        # emulator + Metro + build + install + launch; skips what is already done
scripts/run-android.sh stop   # stop app, emulator, Metro, forwarder, Gradle daemons
```

Measured on this machine: about 30 s from everything stopped (Quick Boot snapshot, warm Gradle
cache) and about 4 s when everything is already running. A first build without Gradle caches
took 5 min 40 s. The script only uses the backend if one is running (see
[Backend](#backend)); the login screen works without it.

Output goes to `/tmp/gopher-android/`: `metro.log`, `gradle.log`, `socat.log`, `screenshot.png`.

Environment variables. These are not in `~/.bashrc`, and the script sets them itself. For manual
commands, paste this into the terminal (or add it to `~/.bashrc`):

```sh
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
export ANDROID_HOME=$HOME/Android/Sdk
export PATH=$JAVA_HOME/bin:$PATH
```

No API keys or `local.properties` entries are needed.

### Restart by hand (what the script does)

Run these from `gopher-fit-front/` with the variables above set.

a. Start the emulator on Windows (or use Android Studio → Device Manager → ▶ `GopherFit_API36`):

```sh
(cd /mnt/c && powershell.exe -NoProfile -Command "Start-Process -FilePath 'C:\Users\nengs\AppData\Local\Android\Sdk\emulator\emulator.exe' -ArgumentList '-avd','GopherFit_API36'")
```

b. Wait until it has booted:

```sh
adb wait-for-device
until [ "$(adb shell getprop sys.boot_completed | tr -d '\r')" = 1 ]; do sleep 2; done
```

c. Start Metro and the IPv4 forwarder. Use two terminals and leave both running:

```sh
npx expo start --port 8082
socat TCP4-LISTEN:8081,bind=127.0.0.1,reuseaddr,fork TCP4:127.0.0.1:8082
```

d. Build and install. `./gradlew installDebug` does not work from WSL (known issue 1), so build,
then install with `adb`:

```sh
(cd android && ./gradlew assembleDebug -PreactNativeArchitectures=x86_64)
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

Leave out `-PreactNativeArchitectures=x86_64` to build a universal APK (all 4 ABIs, 184 MB) for
physical devices.

e. Let the app reach the API on WSL port 3000:

```sh
adb reverse tcp:3000 tcp:3000
```

f. Launch:

```sh
adb shell am start -n com.umnadc.gopherfit/.MainActivity
```

g. Check: `adb exec-out screencap -p > shot.png`, and `adb logcat -d -b crash` should print
nothing.

Stop by hand:

```sh
adb shell am force-stop com.umnadc.gopherfit
adb emu kill                     # adb -s emulator-5554 emu kill if several devices are attached
(cd android && ./gradlew --stop)
# then Ctrl+C the Metro and socat terminals
```

After `adb emu kill`, `emulator.exe` stays in Task Manager for another 10–20 s while it saves
the Quick Boot snapshot. The Windows adb server stays running; stop it with `adb kill-server`
if you want to.

### Script details

`scripts/run-android.sh` runs steps a–g in a faster order: it starts the emulator and Metro, then
builds while the emulator boots. It skips a step when the emulator for `GopherFit_API36` is
already running, Metro already answers on :8082, the forwarder is already up, the installed APK
has the same SHA-256 as the built one, the `adb reverse` rule exists, or the app is already in the
foreground. Gradle always runs, but finishes in about 2 s when nothing changed. After launching,
the script waits for `ReactNativeJS: Running "main"`, then fails if there's a crash-buffer entry,
a `FATAL EXCEPTION`, an `Unable to load script`, or no app process.

Overrides: `AVD`, `ARCH`, `METRO_PORT`, `WIN_SDK`, `JAVA_HOME`, `ANDROID_HOME`, `STATE`.
`stop` only stops the Metro and socat processes the script started (tracked in
`/tmp/gopher-android/*.pid`).

### Backend

The script does not start the backend. Run it in WSL on port 3000 (see the backend's
`docs/deployment.md`), or use the disposable test fixture:

```sh
cd ../gopher-fit-back && uv run python ../gopher-fit-front/tests/serve_backend.py
```

The disposable fixture was used to log in on the emulator with `adb reverse tcp:3000` and to load
the Home tab. Metro embeds `EXPO_PUBLIC_API_URL` when it starts, so restart Metro after
changing `.env`.

## Known issues

These all came up while setting up this machine, and each has a fix.

1. **`./gradlew installDebug` fails with `DeviceException: No connected devices!`.** Gradle in WSL
   looks for an adb server on WSL's own port 5037. The emulator is attached to the Windows adb
   server, which WSL cannot reach in NAT networking mode. The attempt also auto-installed
   `/root/Android/Sdk/platform-tools` and left a Linux adb server running. Fix: use
   `assembleDebug` plus `adb install -r …` (the wrapper passes the path to Windows). Stop the
   stray server with `~/Android/Sdk/platform-tools/adb kill-server`.
2. **Red screen "Unable to load script", and logcat shows `Failed to connect to /10.0.2.2:8081`.**
   Metro listens on IPv6 `::`. The WSL relay publishes that on Windows `[::1]:8081` only, but the
   emulator's `10.0.2.2` (and `adb reverse`) connect to Windows IPv4 `127.0.0.1:8081`. The
   `adb reverse tcp:8081 tcp:8081` that the red screen suggests does not help. Fix: run Metro on
   8082 behind `socat` listening on IPv4 `127.0.0.1:8081` (step c). If a plain `npx expo start`
   is holding 8081, stop it first; the script refuses to continue in that case.
3. **Connection refused right after starting a server in WSL.** The relay to Windows takes a few
   seconds to pick up a new listener. Retry after about 5 s; the script polls from the emulator.
4. **Windows `sdkmanager.bat` from WSL fails with `Package system-images not found. Package
   android-36 not found. …`.** `cmd.exe` splits arguments on `;`. Fix: use the slash form, e.g.
   `sdkmanager.bat "system-images/android-36/google_apis/x86_64"`. It also exits with code 9 even
   on success, so check `…\system-images\android-36\google_apis\x86_64\source.properties`
   instead of the exit code. `avdmanager` needs the `;` form; this worked through PowerShell:
   `echo no | powershell.exe -NoProfile -Command "& 'C:\Users\nengs\AppData\Local\Android\Sdk\cmdline-tools\latest\bin\avdmanager.bat' create avd -n GopherFit_API36 -k '\"system-images;android-36;google_apis;x86_64\"' -d pixel_7"`.
5. **`npx expo prebuild` side effects.** It needs `android.package`; `com.umnadc.gopherfit` was
   added to `app.json`. It also rewrites the `android`/`ios` npm scripts to `expo run:*`; that
   change was reverted, and the script does the same. Its warning `userInterfaceStyle: Install
   expo-system-ui in your project to enable this feature.` is still open. Fixing it means adding
   a dependency, which hasn't been done.
6. **`adb shell am start -W` prints `Status: timeout` on the first launch.** Metro is still
   building the bundle (about 8 s). The app loads anyway; this is harmless.
7. **Yellow toast "Open debugger to view warnings".** It comes from the app's
   `SafeAreaView has been deprecated` warning. It is not an error.
8. **First version of `run-android.sh` did not exit, and `stop` missed Metro.** A bash subshell
   stayed alive holding stdout while Metro ran. Fixed by `exec`-ing Metro, so its pid is the
   process-group leader that `stop` kills.
